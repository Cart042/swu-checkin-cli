# 登录路径性能测量

`scripts/profile_login.py` 只测量登录和只读身份查询路径：先执行一次冷登录，再复用刚刚写入的临时 Token 缓存执行一次缓存命中。每个阶段只调用 `get_token` 和 `get_student_id`，不会导入或调用签到、请假变更、状态写入或推送代码。当前只有一个账号可用，因此没有多账号并发数据。脚本只支持 Linux，因为进程树采样依赖 `/proc`。

在能够访问学校认证服务的主机上运行：

```text
python -m pip install -r requirements.txt
python -m playwright install --only-shell chromium
python scripts/profile_login.py --timeout 30
```

脚本会交互式读取用户名和密码，二者都通过 `getpass` 输入并隐藏回显。`--timeout` 只接受有限的正数，范围为大于 0 且不超过 300 秒。脚本没有用户名或密码命令行参数；不要把凭据放进命令、Shell 历史、仓库文件或 GitHub Actions 日志。凭据只通过父进程到工作进程的标准输入传递，结果中不输出账号标识、响应正文或 Token。

脚本使用权限为 `0700` 的 `TemporaryDirectory` 作为 `SWU_CONFIG_DIR`，Token 缓存只在该目录中短暂存在，两个阶段结束后自动删除。不要把 `SWU_CONFIG_DIR` 指向仓库目录，也不要把真实凭据放进 `.env`、`users.json` 或测试夹具。

输出的成功结果包括：冷登录或缓存命中的墙钟时间、`get_token` 阶段时间、进程树峰值 RSS、观测到的浏览器进程数以及采样间隔。RSS 每 50 ms 从 Linux `/proc` 采样，并把工作进程、浏览器和 OCR 所在进程纳入进程树；它是采样期间的近似最大值，不是内核级精确峰值，短暂出现后退出的进程也可能漏采。进程树 RSS 是各进程 `VmRSS` 的求和，共享页可能被重复计算。`browser_process_count` 是采样到的不同浏览器 PID 数量，不等于浏览器启动次数；脚本不把短暂漏采的 PID 当成启动次数。

工作进程使用独立的进程组。超时、终止信号或工作进程提前退出时，脚本会检查该组是否仍存在，先发送 `TERM`，必要时发送 `KILL`，再以有界方式排空标准输出；因此继承输出管道的浏览器子进程不会让测量命令永久等待。

如果冷登录失败，脚本会跳过缓存阶段，避免在验证码、网络或认证故障时增加登录尝试。如果缓存阶段发现 Token 已失效，脚本会立即失败而禁止进入浏览器登录路径；这样不会把 warm 测量悄悄变成第二次 cold 登录。失败结果只保留异常类型，不把失败响应或账号信息写到报告中。一次完整运行最多包含一次冷登录和一次缓存命中，绝不触发真实签到提交。

本次开发环境未产生可报告的真实性能数字。该环境对 `of.swu.edu.cn` 的直连 DNS 解析失败，且 Playwright Chromium 下载超时，因此没有执行冷登录，也没有伪造缓存命中结果。需要实际数据时，应在能访问学校认证域名并已安装 Chromium 的主机上运行上述命令，将终端中脱敏后的结果另行记录。
